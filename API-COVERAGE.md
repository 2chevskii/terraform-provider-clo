# CLO Terraform provider coverage

Reviewed on 2026-11-19 against release **v2.8.0**, commit `11744b8f4a86a6081acbe99c6a525c4ef8741ae8`. The provider registers 17 resources and 27 data sources. Of 129 operations in the public v2 OpenAPI document, **91 have a Terraform call path, 1 has an unused SDK adapter, and 37 have no provider call**. A call path may serve only refresh, polling or deletion. It does not imply a standalone data source or full control of the request. ### Field and lifecycle changes

| Upstream finding | Fork behavior |
|---|---|
| Instance inputs and destroy | Accepts existing boot volumes, cloud-init and CPU type. Address and storage blocks preserve omitted optional fields. An empty deletion block retains attachments. Explicit lists select attached IDs for cleanup. Omitting the block preserves existing destroy behavior. Use the standalone license resource for quantity. |
| Volume and IP lifecycle | Supports in-place volume metadata updates, cleanup flags, address bandwidth and PTR refresh. Attachment refresh verifies the target. A request to demote a primary IP explains how to promote its replacement. |
| Balancer and DBaaS provisioning | Initial listener rules and an initial database can be created with the parent. DBaaS configuration is also available as JSON with its original value types. |
| Collection reads | Collection readers advance by the actual number of returned rows. List data sources accept query parameters and expose the total count. Explicit limit or offset selects one page. |
| Returned metadata | Project, instance, volume, address, backup and S3 user lookups expose the previously omitted metadata identified below. |
| S3 secrets and quotas | Refresh clears a stored secret when an external rotation changes the access key. Optional quota fields distinguish explicit zero from omission. CLO has no key-revocation operation, so destroying the credential resource forgets it locally. |
| Import | All 21 persistent resource types support import. The remaining resource records a one-time reboot or rescue request. CLO has no retrievable object for that receipt. |

### Verification

- Matched all 129 operation IDs, HTTP methods and paths from the 2026-11-19 public OpenAPI document to production SDK calls and v3.2.96 request builders. The specification SHA-256 was `9f4d175514795f8d723392b0e14342d0ca697941bb9c7faf2f7b4811849fb754`.
- Terraform 1.11.4 loaded 22 resources and 48 data sources from the local build. The Go tests and vet checks passed.
- Terraform imported every persistent resource type against a local HTTP fixture. The combined plan proposed four in-place updates for defaults and configured values and zero replacements. A separate compute apply and follow-up plan verified payloads and stable state for omitted addresses, explicit isolation, existing addresses, and explicit false flags.
- Live acceptance requires an authorized disposable CLO project and credentials. The local tests do not establish service-side validation or asynchronous behavior on a real account.

## Upstream gaps that affect Terraform plans

| Area | Effect | Source |
|---|---|---|
| Server destruction | Destroying an instance or snapshot-restored server requests deletion of its reported addresses and every attached disk with storage type `volume`. The selection uses current attachments, including volumes attached after creation. HCL cannot select which to retain or set the API’s `clear_fstab` option. | [Instance](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/clo/resource_instance.go), [restore](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/clo/resource_snapshot_restore.go), [delete request](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/internal/cloapi/server.go) |
| Server creation | The API accepts an existing boot `volume`, `user_data` and `flavor.cpu_type`. HCL requires an image and block devices and exposes none of those three inputs. HCL accepts `licenses.value`, but the builder discards it. The API license item has only name and addon. | [Resource](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/clo/resource_instance.go), [request](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/internal/cloapi/server.go) |
| Instance updates and refresh | Keypairs and address bandwidth feed creation. Editing those attributes alone has no corresponding update call. Refresh reads ID, name, status and switch status, leaving flavor changes made outside Terraform undetected by the resource. The instance data sources return a wider set of details. | [Resource](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/clo/resource_instance.go), [data source](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/clo/data_source_instance.go) |
| Volumes | Changing the name forces replacement despite the API supporting in-place name and description updates. HCL has no description input. Omitting the name selects autorename implicitly. Extend cannot request a server reboot. Destroy sends an empty body, so force and fstab cleanup cannot be selected. Detach always requests force and omits fstab cleanup. Resource refresh skips size and name. Attachment creation stores the device path, but refresh overwrites it with the attached server ID. | [Resource](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/clo/resource_volume.go), [attachment](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/clo/resource_volume_attach.go), [requests](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/internal/cloapi/volume.go) |
| IP addresses | Standalone attachment omits `bandwidth_max_mbps`. Bandwidth is read-only on the address resource. Changing `is_primary` from true to false invokes the same make-primary action as changing it to true. Attachment refresh reads primary/status/address but does not verify the attached target. Address refresh skips the configured PTR. | [Attachment](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/clo/resource_ip_attach.go), [address](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/clo/resource_ip.go), [requests](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/internal/cloapi/ip.go) |

Project-wide rule discovery and balancer statistics are unavailable. | [Request builder](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/internal/cloapi/loadbalancer.go), [rule resource](https://github.com/clo-ru/terraform-provider-clo/blob/11744b8f4a86a6081acbe99c6a525c4ef8741ae8/clo/resource_loadbalancer_rule.go) |

## Legacy guide

The guide also publishes 111 v1 operations. The provider targets v2 and has no v1 mode. Most legacy capabilities map onto the operation inventory above. Recipes and keypairs now use project-scoped discovery. Floating IP operations map to address operations, including PTR updates. Snapshot and keypair deletion use the v2 delete routes. S3 user operations moved to the v2 S3 paths, with suspend and unsuspend still missing. DBaaS enable/disable and node resize correspond to cluster power and resize operations. Node detail by ID has no dedicated Terraform lookup. Nodes are listed by cluster. The legacy server-scoped PTR action has no server-scoped Terraform equivalent.
